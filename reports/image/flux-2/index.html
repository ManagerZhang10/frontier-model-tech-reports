02 · TL;DR

要点

01

只有博客，没有技术报告

能核对的是产品定位、家族分档、开放情况，以及 VAE 博文里的实验设置与表格。训练数据、完整结构超参和全面基准表都不在这两篇里。

02

流匹配 + Mistral-3 24B VLM + rectified flow Transformer

博客与 VAE 博文的 Architecture 一节一致：在新的 FLUX.2 VAE 潜空间上做 latent flow matching；VLM 提供世界知识与上下文，Transformer 负责空间关系、材料与构图。VAE 博文还写了 SwiGLU，以及更节省计算的全局调制机制（引 Chen et al. 2025）。官方博客 How It Works · VAE 博文 Architecture

03

VAE 瞄准可学习性—质量—压缩的三难

相对 SD-VAE，FLUX.1 把潜空间维度扩大 4 倍并减弱正则，换重建、但可学习性下降；FLUX.2 相对 SD-VAE 扩大 8 倍，并加入语义正则，声称重建与可学习性同时好于 FLUX.1。在为把序列长度对齐到 256 token 的实验配置里（SD / FLUX.1 / FLUX.2 对 latent 做 2×2 patch，RAE 不 patch），SD、FLUX.1、FLUX.2、RAE 每个 token 的通道数分别是 16、64、128、768。VAE 博文 Autoencoders

04

ImageNet 重建与 [dev] 人工偏好是博文里可引用的硬数字

表 1（ImageNet validation）：FLUX.2 AE 的 LPIPS 0.2668、SSIM 0.9038、PSNR 31.4632、rFID 0.1124，四项都优于文中的 FLUX.1 / SD / RAE。图 3 对 FLUX.2 [dev] 的人工偏好胜率：文生图 66.6%，多参考 63.6%，单参考 59.8%。VAE 博文表 1 · 图 3

03 · FAMILY

产品家族（以 2025-11-25 博客为准）

博客把 FLUX.2 写成面向真实生产工作流：多参考一致性、复杂文字、品牌与排版、产品级光照，以及最高 4MP 的图像编辑。所有变体都在同一模型里做文本编辑与多参考编辑。官方博客

  • FLUX.2 [pro]：托管，强调在提示遵循与视觉保真上接近闭源前沿，同时更快、更便宜。Available Now
  • FLUX.2 [flex]：可调步数与 guidance；博客用 6 / 20 / 50 步的示例说明文字准确率和细节与延迟的折中。Available Now
  • FLUX.2 [dev]：32B 开放权重，Hugging Face 可下载，并提供参考推理代码；与 NVIDIA、ComfyUI 合作的 fp8 实现可在消费级 GeForce RTX 上跑。也可经多家 API 调用。商业许可需访问其网站。Available Now
  • FLUX.2 [klein]：博文当时写 coming soon，Apache 2.0，从基座做尺寸蒸馏。本短记不根据 2026 年的后来页面去改写这一条。Available Now
  • FLUX.2 VAE：新的变分自编码器，Apache 2.0 在 Hugging Face 发布，并配有技术博文。Available Now
04 · VAE

架构与 VAE（只写官方博文里有的）

VAE 博文的主线是可学习性（语义空间是否容易被生成模型学习）、重建质量（LPIPS 等）和压缩率之间的三难。作者在不同自编码器的潜空间里训练设置尽量对齐的 flow matching 模型（DiT-XL、ImageNet、分辨率 256×256、batch 256 等）来比较。VAE 博文 Experiments · Trade-off

FLUX.1 VAE 被写成：为了满足 Kontext 一类编辑对高保真重建的需求，把信息瓶颈放宽——潜空间维度是 SD-VAE 的 4 倍，并降低正则权重；重建变好，可学习性下降。FLUX.2 VAE 则把维度放到 SD-VAE 的 8 倍，并引入语义正则（文中回顾了与视觉基础模型对齐、REPA 等路线），声称在编辑所需的高保真和可学习性上同时改进。VAE 博文 Autoencoders

关于通道数：官方原文写的是上述 256 token 对齐配置下「每个 token 的通道数」为 16 / 64 / 128 / 768，同时明确 SD、FLUX.1、FLUX.2 使用 2×2 latent patch、RAE 不 patch。本页按原句转述，不额外反推「未做 patch 时的卷积通道数」，也不编造下采样倍数（博文没有单独给出 f8 / f16 这类说法）。

局限一节还说：牺牲重建的 VAE 往往仍然更好学，他们希望继续缩小这个缺口；并提到初步的文生图实验里，一种不依赖外部表征模型（如 DINOv2 / REPA）的替代做法看起来更好，且预告 FLUX.3。这些都是前瞻，不是 FLUX.2 的已发布规格。VAE 博文 Limitations

06 · LIMITATIONS

局限与存疑

  • 没有技术报告 PDF。训练数据、完整结构超参、全面自动基准和许可正文都不在这两篇官方博文里。本页故意不引用第三方复现或后来的产品页，以免把未核对的数字写进目录。
  • 不要把「每 token 通道数」直接写成裸的 VAE 通道数。128 这个数字出现在「256 token 对齐 + 2×2 patch」的实验配置里。相对 SD-VAE「8 倍维度」与「128 channels per token」可以互相印证，但博文没有另写一句「卷积潜空间为 128 通道、下采样为 f×」。未写的就不写。
  • [klein] 在博文发布时尚未推出。本短记冻结在 2025-11-25 的官方表述。若后来已经发布，应以当时的官方说明为准，而不是改写这篇短记里的「即将推出」。
  • [dev] 的「最强开放权重」是厂商自评（博客与图 3 人工偏好）。图 3 的对照模型名单与评测协议需看原图，本页未转绘。
