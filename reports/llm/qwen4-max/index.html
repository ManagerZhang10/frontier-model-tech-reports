02 · TL;DR

要点

01

同样 2.4T 总参，激活从更多降到 71B

新闻稿称 Qwen4 架构在注意力、残差连接与 embedding 三处升级了稀疏 MoE 设计；总参与 Qwen3.8-Max 同为 2.4T，但每 token 激活 71B，少 25%，以更低推理成本换更强能力。具体结构改动原文未展开。新闻稿 架构段

02

主打编码、Agent 与视觉推理

Code Arena 第 6；另称在 Agents' Last Exam、Vals Index、JobBench、Chartography 上「分数强劲」，但正文未给任何分数。新闻稿 基准段

03

效率数字来自自家专有基准

Work360 覆盖 721 个专业领域的行业任务：整体超过 Qwen3.8-Max，High 推理档少用 35% token，单任务平均成本降约 60%。基准不公开，无法外部核对。新闻稿 基准段

04

开放权重只是预告

Qwen4-Max 本身只通过云 API 与阿里平台提供；「Qwen4 系列更小的开放权重模型将很快发布」，尺寸、许可证、时间均未披露。新闻稿 可用性段

03 · ARCHITECTURE

架构与效率

新闻稿把效率提升归因于新的 Qwen4 架构：沿用稀疏 Mixture-of-Experts，并在注意力、残差连接、embedding三处做了升级。总参数 2.4T，每 token 只激活 71B，比同样 2.4T 规模的 Qwen3.8-Max 少 25% 激活参数。新闻稿 架构段

按「少 25%」反推，Qwen3.8-Max 每 token 激活约 95B推算；新闻稿未直接给出这一数字，此处仅为算术换算。

专家数、路由方式、层数、注意力的具体改法、视觉编码器、训练数据与规模、训练配方：原文均未披露。

安全方面只有定性陈述：软件工程训练在功能测试之外加入代码安全检查；网络安全方向按任务意图过滤训练数据，保留防御类材料、移除攻击类内容；另用专门安全数据集和后训练加强 CBRN 风险防护。没有给出评测数字。新闻稿 Safety 段
