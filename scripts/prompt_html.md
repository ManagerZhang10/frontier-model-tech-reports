# 任务：为前沿模型技术报告写一篇图文并茂、可快速扫读的中文 HTML 深读

你是在为公开站点「前沿模型技术报告」（GitHub Pages）写系列深读。目标读者：做大模型 / 多模态 / 图像与视频生成的算法工程师，尤其关心**图像编辑基础模型的数据构建、评测和 caption**。页面必须让人 2–3 分钟内抓住要点，而不是一篇排版成网页的长 Markdown。

本系列已有一页经确认的样稿风格（暖纸色 + 紫晶色、卡片速览、来源胶囊、sticky 目录、深浅色）。请**沿用当前目录下的 `style.css` 中的设计系统与类名**，不要另起一套视觉。只需为页面特有的 SVG 示意图写一小段 `<style>`。

## 本次输入

当前工作目录里有：

- `paper.txt`：论文纯文本（优先读这个；数字对不上再看 PDF）
- `paper.pdf`：原文 PDF（若存在）
- `figures/`：已从 PDF 裁好的原图，以及 `figures/manifest.json`（含图号、页码、英文题注）。**直接引用这些文件，不要改文件名、不要再生成这些图，也不要伪造「论文原图」。**
- `style.css`：本系列共享样式，请用 `<link rel="stylesheet" href="./style.css">` 引入。
- `notes.md`：若存在，是旧版 Markdown 深读，内容可参考，但**所有数字必须重新对照 `paper.txt`**，不要沿用其中可能过时或写错的日期与数字。

## 输出

保存为当前目录下的 **`index.html`**（单页）。图片用相对路径 `figures/文件名`。字体可用 Google Fonts（Fraunces、Source Sans 3、Noto Sans SC、IBM Plex Mono），并写好系统字体回退。允许少量原生 JS：不要自己写主题/目录脚本，只在 `</body>` 前放 `<script src="./site.js"></script>`（该文件稍后会被挂上；你也可以内联与样稿相同的主题切换 + 目录高亮脚本，二选一即可）。

需要图标就用 inline SVG。不要依赖 Chart.js、D3、Bootstrap、Tailwind CDN。不要用 base64 图片。

页头 kicker 写成：

```html
<div class="kicker"><a href="../../../index.html" class="site-home">前沿模型技术报告</a> · 中文深读 · {{CATEGORY_LABEL}}</div>
```

页脚注明基于哪篇论文、数字均来自原文、图片版权归原作者，并链回 `../../../index.html`。

写完后只把文件写到磁盘，最后一行回复该 HTML 的绝对路径。

## 必须包含的章节（按此顺序，标题可微调但信息不能少）

1. **Hero**：模型名、厂商、日期、论文链接、一句话贡献、徽章行（开源与否、许可证、参数规模、类别）
2. **速览卡片网格**
3. **TL;DR 高亮卡片**（3–5 条，关键数字带来源）
4. **架构**：先放架构/总览原图（如有），再写相对前代或同类的改动。可用 inline SVG 辅助，图下注明「示意」；原文没给的连接关系不要画成确定事实。
5. **数据**（全篇最细）：来源、规模、清洗与过滤、合成数据、caption / 标注方式、配比。没有比例就不要画成百分比柱状图，改用「已披露规模」表，并写明「原文未披露」。
6. **训练配方**：预训练各阶段、后训练、RL；超参原文没给的不要编。
7. **评测**：精选表 + 可选 inline SVG 柱状图（从 0 起或清楚标明）。对比对象写清。带 * / † / 工具号的记号要保留并解释。
8. **新在哪**：3–5 条可核对的新点，不要把常规工程写成创新。
9. **对图像编辑数据 / 评测 / caption 的启示**：这是本系列读者最关心的一节，做成视觉上独立的区块。每条先写论文怎么做（带来源），再写一条可迁移做法，并标明「迁移建议，不是论文内容」。即使这篇不是图像编辑模型，也要从 caption、数据过滤、评测协议里提炼可借鉴处。
10. **局限与存疑**：缺消融、配比未披露、评测不可比、正文与表格不一致、内部集不可复现等。具体、短、不要编造新的质疑。
11. **图表索引**

## 设计要点（与样稿一致）

- 类名尽量使用：`hero` `kicker` `lede` `badges` `badge` `badge acc` `links` `layout` `toc` `sec` `sec-head` `sec-num` `prose` `wide` `card` `glance` `stat` `tldr` `tl` `src` `nd` `fig` `img-pad` `mod` `tbl-wrap` `theme-btn` `topbar`。
- 每个关键数字旁边加 `<span class="src">表 2</span>` 或 `§3.2` 这样的来源胶囊。自己加减要标 `<span class="src calc">推算</span>`。
- 长表、次要细节放 `<details class="more">`，关键结论留在外面。
- 论文原图用 `<figure class="fig card wide">`，中文 caption +「来源：论文图 N」。
- 训练阶段可用 CSS/SVG 流程；数据配比只有原文给出的比例才能画条形。
- sticky 目录、深浅色（`localStorage` 键名 `ftr-theme`）、移动友好。
- 所有外链 `target="_blank" rel="noopener"`。

## 硬性约束（违反即失败）

- **所有数字必须来自原文**（`paper.txt` / PDF），并带来源。禁止编造比例、超参、消融、未给出的数据量。
- **发布日期用 arXiv v1 的 published 日期**：{{V1_DATE}}。若当前 PDF 是 v2 或更新版本，在速览或脚注说明，但主日期用 v1。
- 开源与否、许可证、参数规模以原文为准；原文没写许可证就写「原文未披露」，不要猜。
- 语言：简体中文。模型名、基准名保留官方写法。文风利落，像给同事的精读笔记。
- 不要输出 Markdown 版；不要在 HTML 外再写说明文件。
